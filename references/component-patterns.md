# 组件布局模式（Component Patterns）

读于 Phase 2 写组件前。来自 ui-design-brain（component.gallery 60+ 组件知识库）提炼：每个组件的最佳实践 + 常见布局，按名字查。**写任何组件前先查这一节**，用真实设计系统约定代替通用猜测。

## 导航 / Header

- 高度紧凑 56 至 72px；logo 左，主导航中/右，CTA 在右。
- 主导航 5 至 7 项封顶，其余收进 "More"。
- 长页吸顶；明确当前态；移动端折叠成汉堡或底部 tab。
- 与内容视觉分隔：border-bottom 或极浅阴影，二选一。

## Hero

- 一条清晰标题（clarity 胜过 cleverness）+ 一个主 CTA + 一个可选的次级 CTA。
- 高清大图支撑信息；文字叠图必须有遮罩或安全区保证对比。
- 高度克制：邀请滚动，不霸占首屏。
- 常见布局：左文右图 split，或居中文本 + 下方大图。

## Card

- 卡内层级固定：media → title → meta → action。
- 网格里卡片等高（文字 line-clamp）；整卡可点。
- **边框或阴影二选一，不叠加**；内容克制，详情页承载其余。
- 常见布局：产品网格（图/名/价/CTA）、信息流卡。

## Button

- 三级层次：主（填充）/ 次（描边）/ 三级（纯文字）。
- 动词开头标签（"保存更改"不是"提交"）；触控目标 44x44，桌面至少 36px 高。
- 异步时按钮内显示 loading 并禁用防双击；一个视口区只放一个主按钮。

## Form

- 多数表单单列布局（扫描最快）；移动端 label 在输入框上方。
- 相关字段用视觉邻近分组；blur 时校验而非每次击键。
- 尽量短：只问必要的；提交后错误清晰显示在字段下方。

## Modal / Drawer / Popover

- Modal 少用：只给必须立即注意或聚焦输入的动作。
- 必有关闭途径（X / 取消 / Esc）；焦点圈在弹层内；关闭后焦点还给触发器。
- 内容过长改整页，不让 Modal 内滚动；半透明遮罩压暗底层。
- Popover 从触发器长出（transform-origin），Modal 保持居中。

## Empty state

- 插画/图标软化空感 + 一句帮组标题 + 一个引导 CTA。
- 不责备用户："还没有项目"不是"你没有任何项目"。
- 原位展示（容器内），不做整页接管。

## List / Table / Badge / Avatar

- 长列表（> 5 项）用匹配组件，不用发丝线逐行列表；列表项一致性优先。
- 表格：表头粘性、数字右对齐 tabular-nums、行 hover 态、空态与加载态齐全。
- Badge 只给真实例外（New/Popular 贴满 = 廉价）；Avatar 统一尺寸与圆角。

## 通用铁律

- 留白是特性：先靠留白与色阶分层，边框是最后手段。
- 字体承载层级：display 有性格、正文干净，字重对比最大。
- 一个颜色时刻：中性底 + 一个自信强调色。
- 状态齐全：hover / focus / active / disabled、loading / empty / error，缺一个都不算完成。
- 无障碍硬线：WCAG AA 对比、可见焦点、语义 HTML、键盘全可达。
