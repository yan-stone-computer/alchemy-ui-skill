# 终审：审美与布局审查（Final Review）

构建与图片完成后，交付前执行。顺序：**批判性看（critique）→ 技术查（audit）→ 打磨（polish）→ 冻结**。所有检查在同一轮渲染/截图中批量完成，只允许再修一轮、再确认一轮，然后停止。

## 0. 渲染与证据

- Web/H5：桌面（1440）+ 移动（375/390）至少各一张截图；小程序：开发者工具 375/414 模拟器截图；App：模拟器或真机双端截图。
- 有可视化工具（inline render / browser）就用工具展示，不用文字描述设计。

## 1. 审美审查（Aesthetic Review）

按 [interface-craft.md](interface-craft.md) 的检查项逐条过：

- **签名测试**：能指出 5 个具体元素体现本产品唯一签名吗？"整体感觉"不算。
- **换皮测试（Swap test）**：把字体换成 Inter、把布局换成标准模板，页面还一样吗？一样就是默认化失败。
- **眯眼测试（Squint test）**：眯眼看截图，层级仍清楚、没有刺眼元素跳出？
- **Token 测试**：把 CSS 变量读出来，它们属于这个产品的世界，还是任何项目？
- **焦点与节奏**：每个视图只有一个焦点；间距有呼吸（密区让位疏区）；没有三等宽卡片排满全屏。
- **色彩纪律**：一个强调色贯穿全页；无纯黑纯白；无默认紫渐变；明暗模式层级一致。
- **字体纪律**：非 Inter 默认；serif 有理由；显示层级有 3 档以上（size/weight/color 三杠杆）。
- **动效**：每个动画能一句话说清动机；`prefers-reduced-motion` 生效；无 scroll 监听、无 `transition: all`。<!-- ui-alchemy: ignore -->
- **文案**：重读全部可见文案，无 AI 味（破折号、假精确数字、空洞形容词、"Acme"式品牌名）。

## 2. 布局审查（Layout Review）

- **对齐与网格**：元素是否落在同一基线/间距网格（4px 或 8px 倍数）？无随机 px。
- **视口适配**：各断点无横向滚动、无截断、无重叠；移动端明确折叠；`min-h-[100dvh]`。
- **平台范式**：按 SKILL.md 平台路由逐条核对（小程序安全区/胶囊、H5 viewport/触控、App 系统导航/返回）。
- **层级结构**：信息架构一眼可读；导航一行放得下；CTA 意图唯一且不换行；表单 label 在上、错误在字段下。
- **状态齐全**：hover/active/focus/disabled、loading/empty/error 都在。

## 3. 技术审计（Audit）

- 跑 `python <skill-dir>/scripts/preflight_check.py <target> --platform <h5|miniapp|app>`，硬违规清零。
- 对照 [ux-intelligence.md](ux-intelligence.md) 优先级表：对比度、触控目标、性能、语义标签。
- 性能数据：Lighthouse（Web）LCP < 2.5s、INP < 200ms、CLS < 0.1；小程序首包/分包体积；App 首帧。

## 3b. 大厂评审法（来自 OneRedOak design-review 工作流）

有实时预览环境时，遵循 **Live Environment First**：先实际走一遍交互，再做静态分析。评审按 8 个阶段：

1. **准备**：读 PR/需求动机与变更范围，搭好预览环境，桌面先设 1440x900。
2. **交互与主流程**：走主流程，测 hover/active/disabled 全部状态，验证危险操作确认、感知性能。
3. **响应式**：1440 桌面截图、768 平板、375 移动；无横向滚动、无重叠。
4. **视觉打磨**：对齐与间距一致性、排版层级与可读性、配色一致性、视觉层级引导。
5. **无障碍（WCAG 2.1 AA）**：完整 Tab 序、可见焦点、键盘可操作、语义 HTML、表单关联、alt、对比度 >= 4.5:1。
6. **健壮性**：表单非法输入、内容溢出、loading/empty/error 状态、边界情况。
7. **代码健康**：组件复用、token 覆盖魔法数字、遵循既有模式。
8. **内容与控制台**：全量文案语法与清晰度、浏览器控制台零错误。

### 沟通纪律

- **说问题，不说处方**："间距与相邻元素不一致造成视觉杂乱"，而不是"把 margin 改成 16px"。
- **四档分级**：[Blocker] 必须立即修 / [High-Priority] 合入前修 / [Medium-Priority] 后续改进 / [Nitpick] 细节（前缀 Nit:）。
- **证据驱动**：视觉问题附截图；先肯定做得好的部分再列问题。

## 3c. 五维评分制（交付前打分）

每个交付物在冻结前按五维各打 0 至 10 分，任一维 < 7 分即返工，不允许带着低分交付：

1. **布局节奏**：8pt 网格一致、四种 section 模板轮换、留白有呼吸、无三等宽卡片排满、无卡片套卡片。对照 [layout-system.md](layout-system.md)。
2. **排版层级**：字号阶梯符合 Apple 基准（Hero 72-84 / Section 40-48 / Body 16-17 / Meta 12-13）、三杠杆（size/weight/color）、数字 tabular-nums、无孤立奇怪字号。
3. **色彩纪律**：一主一辅一强调、60/30/10、无纯黑纯白、无默认紫渐变、明暗双套 token 一致。
4. **动效品质**：时间层级正确（按压 180ms / 弹层 300ms / 入场 600ms）、无千篇一律入场、无逐卡闪烁、reduced-motion 生效。对照 [motion-3d.md](motion-3d.md)。
5. **无障碍与状态**：WCAG AA 对比、可见焦点、键盘可达、loading/empty/error 状态齐全、触控目标达标。

打分后把低分项的修复与重测记录进交付说明，不静默过关。

## 4. 打磨与冻结

- 把终审发现的问题**合并成一批**修复，一次改完；再确认一轮截图；有未解问题就明确告知，不静默放过。
- 冻结前检查 [preflight.md](preflight.md) 的完整清单；把 `.ui-alchemy/system.md` 的设计决策存档。
- 交付时给用户：交付物清单、截图/预览、已知限制、后续建议（如需要真实图片、需要真机验证）。
