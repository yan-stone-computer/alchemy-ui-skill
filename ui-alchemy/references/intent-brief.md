# 意图澄清门（Intent Gate）：先问清楚，再开始制作

高级工作流的第一道门。**在意图未澄清之前，不要写代码、不要生成方向、不要出图。** 模糊需求直接开工会浪费整轮返工；一次精确的澄清比三次猜测便宜。

## 何时必须问

当以下任一关键信息缺失时，先问：

1. **产品/主题**：这是什么？解决什么问题？（"做一个 SaaS"不是主题，"一个给独立开发者用的订阅计费后台"才是。）
2. **受众与场景**：谁在用？在什么场景、什么设备上用？（凌晨备课的老师 ≠ 深夜排障的工程师。）
3. **交付平台**：小程序 / H5 / App / 桌面 Web？如果跨端，主端是哪一端？（平台决定范式，见 SKILL.md 的平台路由。）
4. **页面/流程的目标**：用户进来要完成什么"动词"？注册、购买、找资料、看报表？
5. **风格与感觉**：用户有没有关键词、参考站、参考图、竞品？没有的话，你给出 2-3 个方向选项让其选择。
6. **内容与素材**：文案、Logo、品牌色、图片是用户提供，还是需要生成/占位？（影响图片人智能体的工作范围。）
7. **约束与红线**：可访问性、合规、政府/医疗场景、性能预算、上线时间、禁止事项。

## 提问纪律

- **一轮最多 3 个问题**，按优先级排序；不要一次性抛 7 个问题清单。
- 能合理推断的就不问：推断后明确告知假设（"我按 B2B、桌面优先来做，如不对请打断我"）。
- 风格分歧时给选项而不是开放提问："更接近 Linear 的克制，还是 Awwwards 的实验感？"
- 用户回答后，把答案折叠成一份**一句话 Design Read + 3 行以内的关键约束**回显确认，再进入方向阶段。

## 简版提问（快问快答）

> 1. 这个页面/功能给谁用、完成什么？  
> 2. 跑在哪个平台（小程序 / H5 / App / 桌面）？  
> 3. 有没有风格参考或必须遵守的品牌资产？  
> 4. 文案和图片素材由谁提供？（可生成 / 可占位 / 必须真实）

## 产品与主题
- 解决的问题：

## 平台

- 附加约束（安全区、分包、离线等）：

## 范围
- 本次交付的页面/流程：
- 明确不做的：

## 风格
- 关键词：

## 门禁规则

- 简报里"一句话"无法写完整 → 回到提问。
- 平台未定 → 回到提问（平台决定范式，无法跳过）。
- 风格完全空白且用户不愿选 → 按你推断的方向做一版 + 明确标注假设，不再追问。
- 澄清完成后才进入 [design-language.md](design-language.md) 的方向阶段。
