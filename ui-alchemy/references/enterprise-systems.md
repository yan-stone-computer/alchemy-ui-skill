# 大厂设计体系融合（Big-Tech Systems x iOS Craft）

读于需要"大厂质感"的项目：B 端后台、C 端商城、工具 App、社区产品。策略是**借大厂的成熟体系保证工程一致，借 iOS 工艺保证细节精致**，而不是抄某一家。

## 1. 体系选择（先选，再融合）

| 语境 | 首选体系 | 融合方向 |
|---|---|---|
| 电商 / 小程序商城 | WeUI / TDesign Mini / Vant Weapp | 原生控件保可用性，iOS 式圆角卡片与分组列表提质感 |
| C 端工具 App | Material 3 / iOS HIG | Material 的组件密度 + iOS 的留白与动效曲线 |
| B 端后台 | Ant Design / Arco / Semi | 表格表单用体系组件，导航与数据可视化按 Apple 层级 |
| 内容社区 | 小红书/Instagram 式卡片流 | 大圆角图片卡 + 字号层级 + 底部操作栏 |
| 国际化 SaaS | Fluent / Carbon / Primer | 体系语义 token + iOS 式导航与空态插画 |

## 2. 融合的五个抓手

1. **Token 对齐**：把体系的颜色/圆角/间距 token 映射到语义层（`surface/raised`、`text/primary`、`control/radius`），组件从 token 生长，不散落硬编码。
2. **组件用官方的，样式用自己的**：按钮、输入、弹窗用体系组件；覆盖的是 token 而非结构。永远不手写一个已有组件。
3. **导航向 Apple 看齐**：一级入口底部 Tab，二级栈式返回；后台可用侧边栏但保持当前页高亮与面包屑。
4. **数据可视化按"苹果式仪表"**：一个主数字 + 趋势线 + 克制的小图例；不用五颜六色的饼图堆。
5. **空态/错误态带插画与恢复路径**：大厂产品的空态是设计机会，不是默认文案。

## 3. 大厂感 vs 苹果感的取舍

- 信息密度：B 端 12-16px 内边距、表格优先；C 端 20-28px、卡片优先。同一产品内按页面职责切换密度，不全局统一。
- 色彩：大厂体系常用多色状态（成功/警告/危险）；苹果用单一 accent + 语义色。融合时：accent 一个，状态色只出现在语义位置。
- 字体：中文优先系统字体栈（PingFang/HarmonyOS Sans/思源黑体），数字 tabular；不默认 Inter。
- 动效：B 端克制（100-200ms），C 端鲜活（200-350ms + 微交互）。

## 4. 交付检查

- 每个一级页面有导航归属，无孤岛页。
- 表单/表格/弹窗用的是体系组件而非自绘。
- Token 化：全局搜索无散落色值（除图标/插画）。
- 状态四件套（loading/empty/error/disabled）在每个主要页面可演示。
- 深色模式 token 完整，无对比度破洞。
